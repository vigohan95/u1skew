# u1skew

让 Snapmaker U1 打出方正的零件——**不开 Advanced Mode，不改固件**。

u1skew 是一个切片后处理脚本：Snapmaker Orca 切完片后，它按 Klipper `[skew_correction]` 的同一套公式改写 G-code 里的 X/Y（以及 Z）坐标，把机架的歪斜抵消掉。原厂固件、原厂 `printer.cfg`，不会弹保修提示。

[English](README.md)

## 为什么做

打印校准方块后两条对角线不一样长，说明机架有一点不正交。常规办法是 Klipper 的 `[skew_correction]`，在 U1 上就得开 Advanced Mode、手改 `printer.cfg`，论坛上不少人不愿意这么做。u1skew 把同样的补偿挪到切片这一侧。

网上已有通用的 G-code 歪斜脚本，但我们实测它们有三处会在 U1 切片文件里频繁碰到的问题（数字来自 `bench/compare.py`）：

- 只写了 `Y`（或只写了 `X`）的移动原样不动，方框首尾就合不上；
- `G2`/`G3` 圆弧（Orca 的「圆弧拟合」）原样放过，可圆被剪切后是椭圆，圆弧指令画不出来；
- 不跟踪 `G91` 相对坐标和 `G92` 偏移。

| 歪斜系数 xy = 0.01（0.573°） | u1skew 最大误差 | u1skew 闭合缺口 | gskewer 最大误差 | gskewer 闭合缺口 |
|---|---|---|---|---|
| 方框，每行只写一个轴 | 0.000 mm | 0.000 mm | 1.000 mm | 1.000 mm |
| 方框，每行都写 X 和 Y | 0.000 mm | 0.000 mm | 0.000 mm | 0.000 mm |
| 整圆写成 G2（开圆弧拟合） | 0.001 mm | 0.000 mm | 0.100 mm | 1.000 mm |
| G91 相对移动 | 0.000 mm | 0.000 mm | 1.500 mm | 1.500 mm |

「误差」是移动终点和公式算出的应到位置之差；「闭合缺口」是封闭图形首尾差多少。

## 对文件做了什么

- **移动（`G0`/`G1`）**：在机器坐标里变换；只要 X/Y 有变化就两个都写出来，单轴移动也不会错。
- **圆弧（`G2`/`G3`，I/J 或 R 写法）**：拆成 `G1` 折线，离剪切后的真实曲线不超过 0.005 mm；挤出量按长度分配，绝对 E（`M82`）和相对 E（`M83`）都对。
- **`G90`/`G91`/`G92`/`G28`**：输入流和改写后的输出流分别跟踪。
- **换头和 Snapmaker 宏**（`T0`–`T3`、`MOVE_TO_DISCARD_FILAMENT_POSITION`、`TIMELAPSE_TAKE_FRAME`、擦嘴/预挤出等）：逐字节原样保留。固件可能在宏里停靠或换头，所以遇到不确定是否移动的命令后，u1skew 会把 XY 位置当成未知，下一条只写一个轴的移动原样放过，直到出现同时写 X、Y 的移动（Orca 换头后总会写一条）。
- **`EXCLUDE_OBJECT_*`、`SET_*`、温度/风扇 M 指令、注释**：不动，位置照常跟踪。
- **越界**：补偿后有任何移动超出 270 × 270 mm 热床，就**不写文件**，切片软件会显示错误。把零件往中间挪，或加 `--allow-out-of-bounds`。
- **防重复**：文件头加一行标记，同一文件再跑一次会拒绝。

## 安装

需要 Python 3.8 及以上。

```
pip install git+https://github.com/vigohan95/u1skew
```

## 第一步：测量

打印一个歪斜测试方块（Califlower，或 Klipper 文档里的测试方块），用卡尺量：

- `AC`：左前角到右后角的对角线
- `BD`：左后角到右前角的对角线
- `AD`：左边，左前角到左后角

```
u1skew calc --ac 140.4 --bd 142.5 --ad 99.8
```

输出系数（与 Klipper `CALC_MEASURED_SKEW` 同一公式，之前在 Klipper 里量过的系数可以直接用）。量的是角度的话：`u1skew calc --angle 0.2`。

## 第二步：接进 Snapmaker Orca

「工艺 → 其他 → 后处理脚本」填：

```
python -m u1skew fix --xy 0.0035
```

Windows 上可能要写 `python.exe` 的完整路径。Orca 会把临时 G-code 文件路径加在最后，u1skew 原地改写。切片后日志会显示改了多少条移动、最大偏移多少。

不用切片软件：`u1skew fix --xy 0.0035 part.gcode -o part.square.gcode`。

## 换头偏移

U1 每个喷头的 XY 偏移是固件在 u1skew 改完坐标之后叠加的，这段偏移本身没有被剪切，留下的误差是 X 方向 `|Y 偏移差| × xy`（XZ/YZ 系数同理 `|Z 差| × yz`）。Y 偏移 2 mm、xy = 0.0035 时是 0.007 mm，喷嘴打不出这么小的差。

## 验证过什么

- 28 个单元测试，以独立的打印机回放模型为判据（每个移动终点；圆弧每个顶点落在剪切后的椭圆上 ±0.002 mm；3000 步相对移动无累计漂移；换头与宏；Orca 螺旋抬升的整圈螺旋线；测量公式能从构造的平行四边形反推回系数）。
- 用 Snapmaker Orca 2.4.1 和原厂 U1 预设切的真实文件（双喷头、擦料塔、24 次换头、`EXCLUDE_OBJECT`，圆弧拟合关/开各一份）：19,960 / 14,351 个移动终点与公式差都 ≤ 0.0005 mm，所有非移动行逐字相同、顺序不变，总挤出量不变。同样的文件交给 gskewer：88 / 713 个点偏差超过 0.01 mm，最大 0.087 / 0.750 mm。细节见 `bench/RESULTS.md`。
- U1 默认预设关了圆弧拟合，但 Orca 的螺旋抬升每次空驶抬头都会写 `G3 … P1` 螺旋线，u1skew 一样会拆。
- 速度：约 71.5 万行 13 秒。

**还没在真机上打过。** 有 U1 的朋友试了，欢迎开 issue 贴补偿前后的对角线数据。
